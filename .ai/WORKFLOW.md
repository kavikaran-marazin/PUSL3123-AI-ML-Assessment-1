# Team workflow

## Recommended practices (not assessment requirements)

- Agree owners, reviewer, and a backup contact for each task in the team record before work begins.
- Use small, focused Git commits with descriptive messages; review changes made by the other member where practical.
- Coordinate edits to shared notebooks and experiment outputs to avoid overwriting each other's work.
- Keep work reproducible and make decisions visible in documentation or commit history.
- Use branches or pull requests if the team repository workflow supports them; this is a recommendation, not a brief requirement.

## Suggested task cycle

1. Check the official brief and trace the task to a requirement.
2. Agree the owner, expected artifact, and review point.
3. Implement only the agreed scope.
4. Review the change and update documentation.
5. Record completion and outstanding work in `docs/team-and-handover.md`.

Do not infer grading rules or submission requirements from this workflow.
