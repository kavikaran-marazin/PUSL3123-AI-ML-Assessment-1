# Documentation rules

- Label statements as **Official requirement**, **Recommended practice**, **Team decision**, or **Unverified** where confusion is possible.
- Cite the official brief by section, page, or item for assessment requirements. Prefer concise paraphrase over copying long passages.
- Record changes to scope, deliverables, and decisions with a date and enough context for the other member to follow.
- Explain how to reproduce any code or analysis once implementation begins; include environment assumptions and exact commands when known.
- Keep README setup instructions aligned with actual files and dependencies.
- Mark missing information plainly; do not fill gaps with guesses.
