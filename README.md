# PUSL3123 – AI and Machine Learning

Assessment 1 project workspace for a two-member collaborative project at the University of Plymouth.

## Assessment scope

The project brief supplied by the student describes CIFAR-10 image classification in PyTorch across four exercises: MLP, CNN, Regularisation and Generalisation, and Model Width and Depth. These are the only assessment details recorded here. The full official brief was not present when this scaffold was created; see [assessment requirements](docs/assessment-requirements.md) and verify all details against the official brief before implementation.

## Project layout

- `.ai/` — instructions, shared context, workflow, standards, experiment rules, and handover guidance for AI-assisted work.
- `.github/` — repository contribution guidance and collaboration expectations.
- `docs/` — assessment traceability and project documentation.
- `notebooks/` — exploratory or presentation notebooks, if the brief and team workflow call for them.
- `src/` — reusable code, organized by data, models, training, evaluation, and utilities.
- `experiments/` — results, plots, and logs associated with documented runs.
- `checkpoints/` — model checkpoints (normally kept out of Git unless the brief requires otherwise).
- `reports/` — assessment report materials and final deliverables.

## Getting started

1. Read `.ai/AI_INSTRUCTIONS.md` and `.ai/PROJECT_CONTEXT.md`.
2. Add the official assessment brief to the project or record its authoritative location, then reconcile `docs/assessment-requirements.md` with it.
3. Agree roles and communication with both members using `.ai/WORKFLOW.md`.
4. Before coding, confirm deliverables, constraints, dataset handling, and submission rules directly from the official brief.

No models, experiments, dataset downloads, or environment setup are included in this initial scaffold.

## Team

Record both collaborators and their agreed responsibilities in `docs/team-and-handover.md`. Do not commit personal credentials or private contact details.

## Dependencies

`requirements.txt` is intentionally a placeholder until the official brief and team environment are reviewed. Do not install packages based on assumptions.
